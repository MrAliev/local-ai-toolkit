# Политика подписи кода

[English version](code-signing-policy.md)

**Действующие релизы используют подписанный манифест пакета. Подключение Authenticode отслеживается в [#210](https://github.com/MrAliev/local-ai-toolkit/issues/210).**

Установщик проверяет подпись ECDSA P-256 по встроенному открытому ключу, а пакет
сверяет с подписанным манифестом. Authenticode подтверждает издателя исполняемого
файла Windows. Статус этой подписи смотрите в заметках к релизу.
[Что делает установщик](https://mraliev.github.io/local-ai-toolkit/how-it-works.ru.html#что-делает-установщик).

## Указание авторства

После одобрения подписанные через этот сервис релизы будут содержать строку:

Free code signing provided by [SignPath.io](https://signpath.io), certificate by
[SignPath Foundation](https://signpath.org).

## Что подписывается

Только программы, собранные из исходного кода этого репозитория собственной сборкой релиза
проекта:

| Файл | Что это |
| --- | --- |
| `LocalAi.Installer.exe` | установщик; он же удаляет Local AI |
| `localai-launcher.exe` | постоянная точка входа, на которую зарегистрированы все клиенты |
| `localai.exe` | командная строка |
| `codesearch.exe` | командная строка поиска по коду |
| `codesearch-mcp.exe` | сервер MCP поиска по коду |
| `locallm-mcp.exe` | сервер MCP локальных моделей |
| `LocalAi.Broker.exe` | брокер перед Ollama |

Файлы, которые проект не собирает, его сертификатом не подписываются никогда. В том числе
сторонние библиотеки в пакете: `pdfium.dll`, `libSkiaSharp.dll` и `libHarfBuzzSharp.dll`.

## Требования к будущей подписи Authenticode

- Ответственный вручную утверждает запрос на подпись каждого релиза.
- На подпись в SignPath отправляется сборка из исходного кода проверенного
  коммита `main`, выполненная в CI.
- Каждый участник команды пользуется многофакторной аутентификацией в GitHub и в SignPath.
- О программе, подписанной в нарушение этой политики, сообщается SignPath, а релиз, в котором
  она вышла, отзывается.

Эти требования относятся к планируемой интеграции SignPath. Оставшиеся проверки
сертификата и его продления описаны в [руководстве по публикации](publication.ru.md).

## Подтверждения для релиза

**Release from PR** запускает выпуск после слияния запроса в защищённую ветку
`releases`. Сборка использует SHA проверенного коммита `main` из запроса.
Шаги сопровождающего описаны в [руководстве по публикации](publication.ru.md).

1. Сборка создаёт список файлов с хешами неподписанного пакета и установщика.
   GitHub аттестует запуск в `releases`, а в самом списке записан SHA исходников
   из `main`.
2. Задание подписи проверяет материалы сборки, подписывает манифест и сверяет
   пакет по встроенному открытому ключу установщика. Задание публикации сверяет
   хеши загруженных файлов перед открытием релиза.
3. Аттестация опубликованных файлов (`release-asset-receipt/v1`) фиксирует
   хеши четырёх скачанных файлов и идентификаторы релиза и запуска. Поля
   `sourceBuildVerified=false` и `authenticodeVerified=false` относятся к этому
   этапу. Происхождение сборки проверяйте по списку файлов из задания сборки,
   целостность пакета — по подписи манифеста.

Принимайте релиз после успешного завершения всех пяти заданий его запуска.
При проверке опубликованных файлов используйте идентификатор запуска и
ожидаемые хеши. Чтобы подтвердить обновление на конкретном ПК, сверяйте
установленный манифест и версию активного файла.
[Выпуск `0.2.6-rc.1`](https://github.com/MrAliev/local-ai-toolkit/actions/runs/44485801031)
показывает все этапы.

Используются механизмы [действия аттестации](https://github.com/actions/attest)
и [проверки GitHub CLI](https://cli.github.com/manual/gh_attestation_verify).
