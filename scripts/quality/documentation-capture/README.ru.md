# Сбор исходников документации

[English version](README.md)

Этот прогон измеряет часть #622, связанную со сбором исходников. Сравниваются реализация
на `f636319a5ba55bc2f6ff8e9bc62c4864c3d79ff4` и чтение по выбранным типам. Разделение кешей
текста/рендеринга и измерение генерации/валидации/рендеринга остаются отдельной работой issue.

Фиксированный корпус — архив этого коммита и его настоящий опубликованный индекс:
865 семантических документов, 10 877 чанков, CIDX размером 190 908 768 байт. Для корпуса
создаются собственные Git-репозиторий и runtime. Меняются только идентичности репозитория,
поколения и Git; хеши исходников, символы, вхождения, связи, чанки и векторы сохраняются.
Один синтетический коммит даёт обеим версиям одинаковую историю по выбранным путям.

`Capture` включает проверку Git, контрольную сумму настоящего CIDX, загрузку SIDX, проверку
исходников, разбор C#, построение фактов/хешей, историю Git и повторную проверку актуальности.
В него не входят генерация моделью, валидация текста, рендеринг, запись или применение пакета.
Модели не вызываются. Счётчики добавляются только во временные копии исходников:
`SourceReads` считает чтения для документации, исключая собственные чтения проверки Git и
индексов; `SyntaxParses` — разбор C# в `DocumentationInputs`. Выделения памяти считаются
для текущего managed-потока; это не пиковая память процесса.

Для каждого ограничения (1, 5, все) выполняются прогрев и три измерения. Сначала идёт
исходная версия, затем новая; прогоны выполняются отдельно на одной машине с прогретым
файловым кешем. SHA-256 всех сериализованных единиц должен совпасть в шести измерениях
каждого ограничения. Так проверяются выбор типов, содержимое, хеши исходников/ссылок/истории
и порядок. Тесты не требуют заданной скорости. Время и память не считаются экономией
облачных токенов.

## Повторение

Команды PowerShell приведены в [английской версии](README.md#reproduce). Нужен сохранённый
каталог поколения базового коммита (`$generation`) с `manifest.json`, `base.cidx` и
`semantic.sidx`. `$run` должен быть новым временным каталогом задачи; не используйте
пользовательский checkout как fixture.

`Prepare-Probe.ps1` отказывается переиспользовать каталог, извлекает зависимости указанного
коммита и заменяет только два файла сборщика из `SourceRepository` (по умолчанию текущий
checkout). Их SHA-256 записываются до инструментирования. `prepare` создаёт приватный корпус;
`measure` выполняет прогоны; `Save-Evidence.ps1` проверяет совпадение входов и сохраняет
[измерения](evidence/summary.json). Полные исходные результаты хранятся рядом со сводкой.
