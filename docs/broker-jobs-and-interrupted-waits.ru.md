# Задания брокера и прерванное ожидание

[Оглавление](README.ru.md#оглавление) · [English version](broker-jobs-and-interrupted-waits.md)

Команды локальной модели и скачивание моделей с текстовым прогрессом показывают ID задания брокера сразу после его принятия. При `model pull --progress-json` тот же ID передаётся в stderr в прежнем формате прогресса версии 1: `phase="other"`, `status="broker_job:<id>;joined=false"` (либо `joined=true`). Смысл счётчиков скачанных байтов не меняется.

```powershell
localai job status <job-id>
localai job wait <job-id> --timeout-seconds 1800
localai job cancel <job-id>
```

Все три команды поддерживают `--json`. Они обращаются к среде текущей установки по умолчанию и не выбирают другую среду, указанную через `--runtime-root` для адресной проверки status или preflight. Просмотр состояния и отмена не запускают и не перезапускают общий брокер. Если работающий брокер устарел или его возможности не подтверждены, команда возвращает `job_cancel_unsupported`, не принимая неподдерживаемый запрос отмены.

Ctrl+C или таймаут прекращает ожидание этого клиента и сохраняет задание. `job wait` продолжает ожидание **одного задания брокера** и возвращает сохранённый результат внутри границы untrusted-content. Команда не повторяет вызов модели и не возобновляет оставшиеся фрагменты, проверку результата или запись выходных файлов исходной команды. Многоэтапным операциям `triage`, перевода или сборки документации эти действия могут понадобиться и после завершения задания. Само завершение задания брокера ещё не подтверждает завершение всей команды.

Право отмены получает только создатель задания. CLI сохраняет его локально в закрытых записях каталога `client-handles` среды выполнения. Присоединение к уже существующему заданию при дедупликации не даёт права отмены и не стирает ранее сохранённую запись владельца. Знания ID достаточно для просмотра состояния и ожидания, но недостаточно для отмены. Не включайте закрытые записи владельца в диагностические экспорты.

`Requested` подтверждает принятие запроса отмены, а не окончательную остановку. Проверяйте состояние `Cancelled`: при одновременном завершении и отмене задание может успеть завершиться успешно. Если срок аренды исполнителя истёк, брокер с поддержкой отмены проверит сохранённый запрос перед повторным запуском задания. Задания других клиентов продолжаются. Ответы об ошибках скачивания моделей теперь различают `job_wait_detached`, `job_wait_timeout` и `job_cancelled`, указывая исходный `jobId`. Для `model pull` прекращение ожидания и подтверждённая отмена сохраняют код выхода 4; таймаут ожидания возвращает 75, а ошибка сохранения локальных сведений о владельце — 73. Формат записей прогресса скачивания версии 1 остаётся совместимым.
