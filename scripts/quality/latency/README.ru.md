# Проверка задержки поиска

[English version](README.md)

Следующий эксперимент проверяет [кеш векторов запросов в брокере](query-cache.ru.md),
включая стоимость проверки идентичности модели и четыре прогона с одинаковой выдачей.

Эта диагностика сравнивает `SearchService.SearchAsync` с использованием независимого набора данных. Она использует общий локальный брокер LocalAi и установленную политику размещения моделей в памяти. Она не обращается напрямую к Ollama, не изменяет время удержания модели в памяти и не учитывает экономию на токенах облачного сервиса.

Соберите и запустите из PowerShell (замените существующие пути к чистому набору данных и брокеру):

```powershell
dotnet build scripts/quality/latency/LatencyProbe.csproj -c Release
$env:CODESEARCH_LATENCY_REVISION = git rev-parse HEAD
dotnet scripts/quality/latency/bin/Release/net10.0/LatencyProbe.dll `
  <clean-corpus-root> <independent-mixed.json> <output-outside-corpus.json> 34 <LocalAi.Broker.exe>
```

Запуск без одновременной индексации, тестов, OCR или других вычислений. Сохраняйте тот же корпус,
генерацию индекса, двоичный файл брокера, дайджест модели и политику для обеих реализаций.
Для замера базовой версии скопируйте стенд за пределы её рабочей копии и задайте в проекте
ссылку на `CodeSearch.Core.csproj` из этой рабочей копии; запишите его ревизию. Пробный скрипт
записывает идентификаторы источника и корпуса и проверяет стабильность источника в конце. Сравните
дайджесты модели до и после. Неудачный/неполный запуск не является доказательством.

Каждый запуск выполняет поиск по каждому случаю дважды в порядке корпуса. Первый проход включает в себя затраты на первое использование;
второй проход - это повторяемая, "теплая" последовательность. Ни один из них не является принудительным тестом холодной модели. Квантили используют
ближайший ранг: сортируйте проход, извлеките элемент `ceil(p * count)` (с отсчетом от 1). Никакой
порог скорости не должен быть включен в набор тестов.

Границы времени:

- `totalMs`: все обращение к `SearchAsync`, включая чтение фрагментов исходного кода.  Он исключает
  форматирование MCP, транспорт и вызов статуса MCP.
- `beforeEmbeddingMs`: разрешение корня/снимка, загрузка индекса/поиск в кэше, выбор
  overlay и подготовка запроса.
- `embeddingMs`: вызов клиента для создания эмбеддингов, включая запуск брокера, отправку,
  помещение в очередь, опросы, преобразование векторов и нормализацию.
- `afterEmbeddingMs`: ранжирование и создание фрагментов после этого вызова.
- `queueMs` / `executionMs`: длительности очереди и выполнения из квитанции брокера, вложенные в `embeddingMs`.
  Выполнение может включать загрузку модели. Загрузка и вычисления на бэкенде **не**
  предоставляются отдельно существующим интерфейсом для создания эмбеддингов; `backendLoadMs` остается равным null. Эти
  значения не должны добавляться к времени выполнения клиента или считаться временем чистого вычисления.

Необязательный шестой аргумент `cache` запускает прототип диагностики: векторы запросов
используются повторно только после чтения дайджеста модели через отдельную задачу Tags брокера. В случае пропусков,
дайджест проверяется повторно после создания эмбеддинга. Этот прототип ограничен пробным скриптом,
содержит не более двух записей для каждого случая в этом двухпроходном запуске и не является производственным кэшем.
`identityMs` находится внутри `embeddingMs`; `cacheHit` определяет повторное использование. Он специально
измеряет стоимость безопасной проверки идентификатора, а не кэширования с помощью изменяемого тега.

## 2026-09-21: повторное использование одного свежего снимка в каждом поиске (#619)

Базовая версия: `7105a22a51b37fd8d5c57a7a1ca98ab48ffa264c`. Кандидат: эта ревизия
с изменением снимка, относящимся к области запроса, в этом PR. Установленная версия брокера:
`f10ff0ec19a5`; артефакт кандидата содержит точные хеши брокера и ядра SHA-256.
Оба запуска использовали один и тот же установленный брокер; установленный runtime не обновлялся.
Первоначальный пробный скрипт не сохранял хеши двоичных файлов; его артефакт оставляет эти поля пустыми. Пробный скрипт,
который вынесен в репозиторий, сохраняет их для последующего воспроизведения.

Смешанный корпус был чистым на коммите `2a9b6285b7a7bbecf2c826ae41d3bdd53aabf94e`,
дереве `4d6f312ef41ca1372a3816738ab9afaa5a1e5ec5`, 87 файлов / 227 фрагментов, с генерацией
`1364bc2a1d1891bae169bc138d397cc633055e64e824193014fd010383fd364b`.
Модель: `qwen3-embedding:8b-q8_0`, неизменный дайджест
`9704fd987c12aa746934ea9f99dc85527c83c6e4b98b3a10b94689332ee866bb`.

Теплый проход, 34 английских/русских случая C#/TypeScript/Python и случаи без ответов, миллисекунды:

| Граница | До p50 | После p50 | До p90 | После p90 |
| --- | ---: | ---: | ---: | ---: |
| Весь SearchAsync | 650.20 | 319.96 | 678.35 | 424.77 |
| До создания эмбеддинга | 440.68 | 189.97 | 454.83 | 204.97 |

Подтверждённый эффект правки — сокращение подготовки снимка примерно на 250 мс. Медиана
создания эмбеддинга также варьировалась между запусками; не приписывайте эту дополнительную разницу
этому изменению. Это один последовательный запуск "до и после" на одной машине с Windows, а не
общая гарантия производительности, тест параллельной нагрузки или сквозной результат MCP.

Все 68 списков результатов точно совпадали, включая порядок и оценки. Показатель recall@10 для "теплого" прохода
остался на уровне 0.9666666667, precision@5 - 0.1933333333, средний ранг первого релевантного результата - 1.7666666667,
и коэффициент ложноположительных результатов для случаев без ответов - 0.5. Последнее является существующим ограничением качества.
Каталог с результатами сохраняет время выполнения для каждого запроса, SHA-256 полных сериализованных списков результатов
и оба отчета о качестве. Оценки использования облачных токенов в отчетах о качестве не являются измеренными
экономиями для этого бенчмарка.

`Save-Evidence.ps1 -InputDirectory <raw-output-directory> -OutputDirectory <evidence-directory>`
ожидает наличие файлов `baseline.json`, `after.json`, `pilot-cache.json` и соответствующих им
сопутствующих файлов результатов стенда. Скрипт хеширует полные массивы результатов (включая пустые массивы), проверяет соответствие
идентификаторов корпуса/модели и все 68 извлечений, и исключает не относящуюся к делу информацию об установленных моделях.

Отдельный пилотный запуск с кэшированием дайджеста для четырех случаев занял примерно 2.68 секунды, даже при попадании в кэш:
каждый поиск идентификатора сам по себе стоил примерно 2.24 секунды. Он был отклонен. Это не является
сравнением производительности для 34 случаев, и его общие показатели качества охватывают только эти четыре случая.

Этот инкремент оставляет открытым пункт #619: кэширование векторов с проверкой digest на уровне брокера, отдельно
выделенное время загрузки/вычислений модели, семантика точных символов, принудительные "холодные"/параллельные запуски
и измерения удержания модели при чередовании поиска, чтения файлов и OCR. Ранжирование и политика размещения моделей в памяти не меняются. Новый поиск по-прежнему
проверяет репозиторий Git и определяет текущее поколение индекса; удаляется только повторяющаяся проверка в рамках одного вызова.

Первичный перевод: локальная модель translategemma:12b; технические термины проверены и исправлены.
