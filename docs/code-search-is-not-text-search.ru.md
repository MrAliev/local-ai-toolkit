# Поиск по коду — не текстовый поиск

[Оглавление](README.ru.md#оглавление) · [English version](code-search-is-not-text-search.md)

Файл не рубится на равные ломти текста. Он **разбирается по объявлениям** — класс, метод,
функция, — и каждое из них получает свой кусок вместе со своим именем, сигнатурой и точными
строками. Объявление, которое не помещается в один кусок — 6 000 символов вместе с
заголовком, — режется на перекрывающиеся части с номерами вида `[1/3]`. Поэтому попадание —
это `OrderCloser.CloseAsync` или одна его пронумерованная часть, а не случайно совпавшая
строка посреди чужого метода.

- **C#** разбирает **Roslyn** — тот же компилятор, что собирает проект. Он строит настоящее
  синтаксическое дерево. Тип получает один кусок: объявление и по строке на каждый член —
  поля как написаны, остальное сигнатурой. Свой кусок получают каждый метод, конструктор,
  деструктор, оператор, оператор преобразования и индексатор, а также свойство с настоящей
  логикой: аксессором с телом или телом-выражением длиннее 80 символов. Файл без объявления
  типа становится одним куском целиком.
- **TypeScript и Python** размечают индексаторы **SCIP** — `scip-typescript` и `scip-python`.
  Если индексатор сообщает границы объявления, кусок идёт по ним; если только имя — кусок
  тянется от этого объявления до строки перед следующим. По отступам ничего не угадывается.
- **Всё остальное** — разметка, конфигурация, документация, языки без индексатора — разобрать
  так нельзя, поэтому там честное скользящее окно: 60 строк с перехлёстом в 12, чтобы мысль
  не разорвало на стыке.

Чего индекс не видит — файла, который Вы правите, но ещё не сохранили. Навигация по нему
всё же отвечает, но только когда агент передаёт текст буфера: из командной строки такого
пути нет, а языковые серверы выключены, пока Вы их не включите.
