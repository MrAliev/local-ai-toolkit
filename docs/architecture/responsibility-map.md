# Responsibility map for incremental changes

[Русская версия](responsibility-map.ru.md)

This completes the boundary review in [#624](https://github.com/MrAliev/local-ai-toolkit/issues/624), against `78b7da480634313ff97b96b0eb1fbe5ecd32aecc`. The six files below remain production entry points. Their length is not a reason to move code. A further extraction needs a concrete behavior change, a named caller and a test of the observable guarantee it must preserve.

| [DurableQueue](../../src/LocalAi.Broker.Core/DurableQueue.cs) | Admission/deduplication and sequence allocation, durable state and leases, validated request payloads, recovery, archive/quarantine and retention. | Metadata, payload validation and retention are distinct responsibilities inside one mutex transaction. The request cache is scoped to the current mutex lease. A helper must receive that scope or validated values; it must not acquire an independent lock or cache payloads across operations. State-only polling must remain state-only. |
| [BrokerModelInstaller](../../src/LocalAi.Installer.Core/Models/BrokerModelInstaller.cs) | Trusted request snapshot, signed catalog validation, active-version lease, launcher commands, status/pull/preflight protocol validation, progress and accurate partial outcomes. | Existing trust/active-version/process interfaces are seams, not public trust bypasses. A new protocol field may justify a narrow parser/validator; it must return facts to the batch owner, which retains trust lifetime, cancellation and the distinction between attempted, completed and indeterminate effects. |
| [InstallationLayoutLease](../../src/LocalAi.Installer.Core/Activation/InstallationLayoutLease.cs) | Protected Windows layout acquisition, retained directory/file handles and identity/ACL evidence, version temporaries/publication, launcher backup/retention and owned cleanup. | No additional extraction is selected. For a concrete publication/backup defect, isolate only the affected operation while the lease keeps its handles and evidence alive. A helper must not replace handle-relative operations with a path check followed by an unprotected operation. |
| [IndexBuilder](../../src/CodeSearch.Core/Indexing/IndexBuilder.cs) | File partition/reuse, symbol-aware chunking, base/overlay assembly, broker embedding batches, checkpoint resume, adaptive limits, backend recovery and build progress. | No additional extraction is selected. A measured assembly, retry or checkpoint defect may justify one private plan/phase helper. Preserve hashes, chunker identity, model/dimension/context and ordering in its inputs. Writing an index does not grant that helper authority to publish the repository generation. |

The last two decisions are deliberately conditional: #624 does not authorize a standalone rewrite of security or indexing code. There is no new abstraction without a consumer, persistent queue cache, storage migration or public API change in this documentation change.

## Guarantees to preserve

**Installer and model execution.** Consent precedes effects. Journal/result facts determine what completed, failed or remains unknown; formatting cannot change those facts or rollback eligibility. The model batch keeps verified package, launcher and active-version evidence throughout execution, matches catalog/model/context in command responses, preflights installed models and never silently relaxes residency. Existing guards include [wizard tests](../../tests/LocalAi.Installer.Tests/InstallerWizardViewModelTests.cs) and [model installer tests](../../tests/LocalAi.Installer.Core.Tests/BrokerModelInstallerTests.cs).

**Sync and indexing.** The repository gate precedes shared-state writes and owns the whole publication transaction. Semantics and corpus must describe the same generation/tree/dirty state. A changed worktree cannot publish stale artifacts; an early worktree pointer is valid only for its recorded global-pointer epoch. Cancellation/failure must preserve readable published generations and completed checkpoints. Keep base/overlay model dimensions, chunker identity and normalization consistent, including unchanged-file reuse. Existing guards include [active publication](../../tests/LocalAi.IntegrationTests/ActiveWorktreePublicationTests.cs), [pointer epochs and retention](../../tests/CodeSearch.Tests/WorktreeGenerationPublicationTests.cs), [embedding resume](../../tests/CodeSearch.Tests/EmbeddingCheckpointTests.cs), [backend recovery](../../tests/CodeSearch.Tests/ABuildWaitsForABackendThatDiedTests.cs) and [adaptive batching](../../tests/CodeSearch.Tests/AdaptiveEmbeddingBatchTests.cs).

**Queue.** A shared mutex protects sequencing, deduplication, request/state consistency, lease transitions and recovery. Validated payloads do not outlive that lease, including exceptional exits. A same-length/backdated replacement must be checked on the next operation; invalid records are quarantined. Preserve durable JSON contracts and archive/retention semantics. [QueueRequestSnapshotTests](../../tests/LocalAi.Broker.Tests/QueueRequestSnapshotTests.cs) checks these cache boundaries; [the retained measurement and real-process contention probe](../../scripts/quality/queue-reads/README.md) covers the measured change.

**Protected installation layout.** Keep canonical identity, ACL/reparse validation and retained handle lifetime coupled to the operation. Revalidate before committing/publishing; rollback/cleanup removes only owned changes. A path string is not a substitute for retained evidence. [Package installer tests](../../tests/LocalAi.Installer.Core.Tests/LocalAiPackageInstallerTests.cs) include unsafe-existing-ACL refusal without mutation; [shared-root tests](../../tests/LocalAi.Installer.Core.Tests/InstallationLayoutSharedRootTests.cs) cover permitted existing layout state. These are regression anchors, not proof of every possible filesystem race.

## Acceptance of the next small PR

1. Name the issue, caller and observable scenario requiring the boundary. Keep one responsibility change per PR and preserve the existing entry point unless the issue requires a contract change.
2. For changed behavior, reproduce the failure first. For an extraction, retain existing observable tests and add a test only for an uncovered guarantee. Do not test a new helper merely because it exists, or assert a machine-speed threshold.
3. Carry lock/lease lifetime, cancellation, ownership and publication authority across the boundary explicitly. Preserve JSON contracts and untrusted-content markers. Compare results on the existing corpus before accepting an optimization.
4. Run the full solution before opening the PR: `dotnet test LocalAi.slnx --configuration Release --max-parallel-test-modules 1 --timeout 20m`. Record totals and reasons for skips. Unit/fixture checks do not establish live DPI, accessibility or installation acceptance.

For this map, implementation and test anchors were checked against the cited baseline. No production code or tests were changed. The PR records the full-suite result and verifies local document links. No model-performance or cloud-token-savings claim is made.
