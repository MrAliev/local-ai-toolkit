## Как подписывается и публикуется релиз

Откройте PR с файлом `.github/release-request.json` в защищённую ветку `releases`. В запросе на выпуск укажите версию и точный коммит из `main`, для которого прошла проверка **Build and test**. После успешных проверок и слияния PR сценарий **Release from PR** собирает пакет из указанного коммита, автоматически подписывает манифест и проверяет пакет. Перед публикацией он проверяет загруженные в черновик файлы, затем фиксирует хеши опубликованных файлов.

```mermaid
flowchart TB
  request["PR с запросом на выпуск в releases"] --> check["Проверить запрос и CI исходного коммита"]
  check --> merge["Слить PR"]
  merge --> build["Собрать из указанного коммита main"]
  build --> sign["Подписать манифест и проверить пакет"]
  sign --> assets["Проверить файлы черновика и опубликовать"]
  assets --> record["Зафиксировать хеши опубликованных файлов"]
```

Не изменяйте пакет после подписания манифеста. Поля запроса, правила предварительных выпусков и шаги проверки описаны в [руководстве по публикации](../publication.ru.md).

Authenticode предназначена для подписи собственных исполняемых файлов проекта под Windows. План внедрения и правила для сторонних DLL описаны в [политике подписи](../code-signing-policy.ru.md).
