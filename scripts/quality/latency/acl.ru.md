# Не перезаписывать уже точные ACL runtime (#619)

[English version](acl.md)

Каждый стандартный клиент брокера защищает дерево runtime в Windows. CodeSearch
создаёт такой клиент при каждом запросе эмбеддинга. Прежняя реализация перезаписывала
и затем проверяла каждый ACL, даже уже точный. Предварительный замер этапов показал
1440–1533 мс на эту работу против примерно 290 мс на повторный SearchAsync с уже
созданным клиентом. Формирование статуса добавляло примерно 390–410 мс. Эти числа
помогли выбрать цель; они не заменяют сравнение до и после, описанное ниже.

`RuntimeAcl.Ensure` теперь читает реальные ACL и восстанавливает только несовпадение.
Начальная проверка и проверка после исправления используют один валидатор. Решение
не кешируется: каждый вызов обходит дерево и проверяет каждый встреченный объект.
Сохраняются требования защищённых явных записей полного доступа для текущего
пользователя и администраторов, точных флагов наследования и распространения,
отказ на reparse point и обработка перемещённых заданий. Если первое чтение ACL
запрещено, выполняется попытка восстановления с обязательной последующей проверкой;
прочие ошибки доступа не игнорируются. Новые объекты и изменённые права по-прежнему
восстанавливаются.

Изменение относится к Windows. Путь для других ОС, политики очереди и кеша брокера,
ранжирование и контракты отчётов использования не меняются. Установленный RC22
не обновляется этим изменением исходников.

## Воспроизведение сравнения полного MCP-вызова

До редактирования соберите и сохраните весь каталог
`CodeSearch.Mcp/bin/Release/net10.0` на базовой ревизии
`f30b4d17243ec8a06c711b8eb614ecdd6543ceb9`. Соберите кандидат и сохраните отдельный
каталог. В каждом нужны обычные соседние файлы брокера для штатного разрешения
пути при запуске клиента. Оба клиента используют уже работающий общий брокер RC22;
не заменяйте и не перезапускайте его между прогонами.

```powershell
python scripts/quality/latency/acl_probe.py `
  <clean-mixed-corpus> <cases.json> <baseline-client-directory> `
  <candidate-client-directory> <new-output-directory>
dotnet run --project scripts/quality/acl-identity/AclIdentity.csproj -c Release -- `
  <baseline-client-directory> <candidate-client-directory> <output-directory>/code-identity.json
python scripts/quality/latency/save_acl_evidence.py `
  <output-directory> <evidence.json>
```

Не запускайте параллельно тесты, индексацию, другие модельные задачи и изменения
конфигурации или моделей. Порядок: базовая версия, кандидат, кандидат, базовая версия.
Каждый прогон запускает свежий постоянный MCP-процесс и выполняет все 34 независимых
запроса корпуса дважды. Общий брокер, кеш ОС и кеш векторов не сбрасываются. Digest
моделей здесь не записывается; замена моделей во время прогона запрещена. Обычная
очистка архивов и рост дерева runtime не заморожены: это замер работающей системы
на одной Windows-машине, а не тест ACL на дереве фиксированного размера.

Таймер охватывает полный цикл JSON-RPC, поиск, формирование статуса и отчёта
использования. Запуск процесса и проверки индекса на границах прогонов исключены.
Параметры: topK=10, maxPerFile=3. Во всех восьми проходах для каждого запроса должны
совпасть все отображённые результаты, порядок, округлённые оценки, сигнатуры,
идентификаторы чанков и фрагменты; случайные nonce границ недоверенных данных
исключены. Полная точность внутренних оценок через MCP не доступна. Проверка
равенства не заменяет независимый базовый замер качества и не улучшает известные
ограничения запросов без ответа.

Валидатор требует четыре полных прогона по 68 запросов, неизменные коммит корпуса,
путь индекса, политику, процесс брокера и хеши файлов каждой версии. Хеши DLL между
сборками различаются; отдельная проверка подтверждает одинаковые инструкции методов,
сигнатуры, локальные сигнатуры, области исключений, строковые литералы и ссылки на
сборки в CodeSearch.Mcp, CodeSearch.Core и Broker.Client. Она привязана к точным хешам
измеренных файлов. Производственные изменения исходников Git затрагивают только RuntimeAcl.
Сохраняются время каждого запроса и хеш отображённой выдачи; фрагменты исходников
и условные оценки токенов исключаются. Экономия облачных токенов не заявляется.

## Корректность

Новый регрессионный тест с бюджетом операций сначала упал на старой реализации
с `ACL write budget exceeded`. Он читает реальные ACL всех объектов уже защищённого
временного дерева и разрешает ноль записей. Другой тест на реальной файловой системе
меняет субъектов доступа одного дочернего файла и проверяет восстановление только
этого файла при неизменном содержимом соседнего. Тест восстановления проверяет
обработку отказа первого чтения и последующую валидацию после записи. Существующие
тесты покрывают ошибку записи ограничительного DACL, неверные записи, права и
наследование, исчезнувшие задания, выход через junction и циклы. Ни один тест не
проверяет скорость конкретной машины.
